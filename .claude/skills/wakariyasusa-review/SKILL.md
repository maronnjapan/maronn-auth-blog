# わかりやすさレビュー

文章を「分かりやすさ」の観点で診断し、**具体的な改善案**まで出すためのスキル。

## 大前提となる考え方

分かりにくさは書き手のセンスではなく、**情報の整理不足**から生まれる。だから直せる。レビューの軸は次の3つ:

1. **受け手は「わがままなお客様」** — 自分から努力して読んではくれない。送り手が整理すべき仕事を受け手に押し付けていないかを常に疑う。
2. **「分からないのはお前が悪い」は禁句** — ちゃんと書いてあるのに伝わらないなら、書き方が悪い。
3. **直すのは表現であって内容ではない** — 中身を削るのは最後の手段。まずは構造化・順序・粒度・視覚化で解く。

## いつ何をするか

- **既存の文章を渡されたとき** → 下記「レビューの手順」でレビューする。
- **自分が長い解説・ドキュメントを書くとき** → 書いた後に「セルフレビュー」の観点で読み返してから出す（特にルール04・05・07・09・15）。
- **「全部直して」と言われたとき** → 指摘だけでなく書き直し版（リライト）を提示する。

## レビューの手順

### 1. 受け手を確定する（ルール02・03・14）

レビューの前に必ず受け手を言語化する。受け手が不明なら**先に確認する**。これを飛ばすと指摘がぶれる。

- 誰が読む？（年齢層・職種・初心者/中級者/上級者）
- 前提知識はどこまで持っている？
- どれくらい熱心に読む？（流し読み前提か、腰を据えて読むか）
- どの専門用語が「説明なしで通じる」か

### 2. 16ルールで診断する

下の一覧で当てはまる問題を探す。**全ルールを機械的に当てない**。その文章で実際に効くルールに絞る（普通は3〜6個）。各ルールの詳細チェック項目は `references/checklist.md` を参照。

| # | ルール | 効く場面 |
|---|---|---|
| 01 | おもてなしの心を持て | 全般。受け手目線になっているか |
| 02 | 受け手のプロフィールを設定せよ | 想定読者が曖昧な文章 |
| 03 | 受け手の熱意を見極めよ | 長文・分量過多・流し読みされる文章 |
| 04 | 大前提の説明を忘れるな | 専門的な文章、書き手が詳しすぎる場合 |
| 05 | まず全体地図を、その後現在地を | 章立て・手順書・長い解説 |
| 06 | 複数解釈を許すな | 指示文・仕様・代名詞や修飾が曖昧な文 |
| 07 | 情報のサイズ制限を守れ | 一文・一段落が長い、一度に出す量が多い |
| 08 | 欲張るな、詳細を捨てよ | 情報を詰め込みすぎ |
| 09 | 具体的な情報を示せ | 抽象論・概念説明だけで終わっている |
| 10 | 情報に優先順位をつけよ | 重要情報が埋もれている |
| 11 | 情報を共通項でくくれ | 繰り返しが多い、冗長 |
| 12 | 項目の相互関係を明示せよ | 階層・並列がごちゃ混ぜ |
| 13 | 視覚特性を重視せよ | べた書き。表・箇条書き・図で解けるもの |
| 14 | 自然発想に逆らうな | 並び順・配置が直感に反する |
| 15 | 情報の受信順序を明示せよ | どこから読めばいいか分からない |
| 16 | 翻訳は意味を訳せ | 翻訳文・直訳調・原文構造に引きずられた文 |

### 3. 指摘する（場所＋理由＋直し方）

各指摘は必ず3点セットで書く。これがないと受け手（＝依頼者）が直せない:

- **どこが** — 該当箇所を引用または位置で特定する
- **なぜ問題か** — どのルールに照らしてどう伝わりにくいか
- **どう直すか** — 抽象的な助言ではなく具体的な書き換え案

### 4. リライトを出す

依頼が「直して」「改善して」なら、指摘の後に**書き直した全文**を出す。改善後がどう良くなったかを1〜2行で添える。

## 出力フォーマット

```
## 受け手の想定
（誰が・どの前提知識で・どれくらい熱心に読むか。不明なら確認する）

## 良い点
（既にできていること。1〜3個。削らないよう守るべき箇所も含む）

## 改善ポイント
### 1. [ルール名] 一言サマリ
- 該当: 「（引用）」
- 問題: （なぜ伝わりにくいか）
- 改善: （具体的な書き換え案）

### 2. ...

## リライト版（依頼が「直して」の場合）
（書き直した全文）
```

## やってはいけないこと

- **指摘の羅列で終わらない。** 「分かりにくい」とだけ言って直し方を示さないのは、このスキルが一番嫌う「受け手への押し付け」そのもの。
- **16個すべてに無理やり当てはめない。** 効かないルールを並べると指摘が薄まる。
- **内容の正しさのチェックと混同しない。** これは「分かりやすさ」のレビュー。事実誤認・技術的な誤りの指摘は別軸として、混ぜるなら見出しを分ける。
- **受け手を確認せずに進めない。** 想定読者で指摘の中身が大きく変わる。

## 図解を提案・作成する場合（ルール13）

「表にできないか」「図解できないか」は強力な改善策。ただし図を作る場合の体裁ルール:

- **線・矢印（エッジ）の上に文字を重ねない。** ラベルは線の脇に置く。
- **白黒のみで作る。色は使わない。** 区別は形・太さ・位置・枠で表現する。
